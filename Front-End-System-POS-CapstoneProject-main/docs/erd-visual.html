ERD — Front-End System POS Capstone Project

9 entitas · 8 relasi · model diturunkan dari kode src/ + docs/ERD.md + dokumen Perencanaan Sistem

Catatan sumber: model ini disusun untuk project POS frontend ini (React + Vite, state di PosContext, data mock di src/data/initialData.js). Entitas backend Codasuaka yang tidak ada di project ini — Instansi, Outlet, KategoriTransaksi, TransaksiKas, ApprovalLog — serta Stok sebagai tabel terpisah (di sini stok adalah kolom pada produk) tidak dimuat. Multi-tenancy / TenantScope juga tidak relevan karena project ini tidak punya backend. order_type dan payment_method dimodelkan sebagai atribut enum, bukan tabel, karena di kode keduanya memang literal string.

Sudah Ada di Kode (project ini)

  • • produk — INITIAL_PRODUCTS: id, name, sku, category, price, stock, image, description
  • • kategori — INITIAL_CATEGORIES: id, name, icon (kopi, non-kopi, makanan, snack, dessert)
  • • transaksi — INITIAL_TRANSACTIONS: id, date, cashier, orderType, tableNumber, customerName, subtotal, tax, discount, total, paymentMethod, amountPaid, change, status
  • • item_transaksi — array trx.items[]: id, name, price, quantity, note
  • • keranjang — state cart[] di PosContext (sementara, tidak dipersist)
  • • Persistensi saat ini localStorage: pos_products, pos_transactions

Direncanakan (docs/ERD.md)

  • • pelanggan — id, nama, email, phone, alamat, npwp, created_at, updated_at
  • • diskon — id, kode, nama, tipe, nilai, masa berlaku, kuota, used_quota, aktif
  • • loyalty_program — id, nama, poin_per_rupiah, rata_poin_ke_rupiah, aktif
  • • user — id, nama, username, role (admin/kasir), shift — untuk RBAC sesuai dokumen Perencanaan Sistem
  • • Planned change 1: transaksi.customerName (string) → transaksi.pelanggan_id (FK)
  • • Planned change 2: produk.category (string) → produk.kategori_id (FK)
  • • Planned change 3: transaksi.cashier (hardcoded) → transaksi.kasir_id (FK)
